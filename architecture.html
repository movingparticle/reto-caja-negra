FRONTIER Bogotá 2026 · Reto 2 · hito 12:00.
Un servicio lleva 10 años en producción y nadie sabe cómo funciona. Vamos a descubrir su comportamiento observándolo y construir una réplica que responda exactamente igual — errores incluidos — sin llamarlo nunca en ejecución.

01 // qué

Reemplazar un sistema sin código ni documentación por una réplica determinista, byte a byte, frente a casos que no conocemos.

02 // cómo

Probing guiado por hipótesis para inferir la regla real, y un servidor HTTP nativo en memoria que emula comandos, estados y errores.

03 // prueba

Comparación diferencial oráculo vs. réplica, batería adversarial y paridad exacta de status y cuerpo.

Worker

Entrypoint de producción: CORS, ruteo, auth timing-safe y límite de cuerpo 8 KiB (E101). Rutas desconocidas → 404 E404.

Durable Object

Instancia única global-caja-negra: garantiza un solo estado entre requests, aislado por POST /__reset.

Motor + checksum

Máquina de estados determinista. Control con ISO 7064 Mod 97-10; precedencia de errores y reversión de ANULA.

Runtime de un test

POST /__reset → estado 0 → POST /msg (1 a 12 requests) → validación → transición → cuerpo exacto. Más de 5 s es fallo.

Despliegue

Worker + Durable Object en el edge de Cloudflare. Un único estado lógico; verificado en vivo (20/20 ejemplos).
